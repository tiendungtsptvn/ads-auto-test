## Hướng đi đã chốt

- **Chuẩn so sánh (D-097):**
  - Giá trị key trên Firebase dưới condition `Tester_<versionName>` là giá trị đúng.
  - Log là đối tượng được test, không dùng làm chuẩn.
  - Chỉ xét condition `Tester_<versionName>`, bỏ qua mọi condition khác (D-095).
  - Key không có giá trị riêng cho condition này thì so với giá trị default, kèm ghi chú "chỉ có default (prod)" (D-096).
- **Log chỉ dùng để biết load, show, thứ tự (D-101).** Giá trị Remote Config in trong log không dùng để xác định bug; key không có trong log không phải bug. Chỉ ad có key = `true` mới cần load/show (D-102).
- **Phạm vi:**
  - Kiểm mọi key remote của các ad trong file kịch bản.
  - Trạng thái bật/tắt dùng trong `verify_ads` lấy từ console, kể cả key nhóm FO (D-097).
  - Key có giá trị không phải `true`/`false` thì không tự kiểm, chỉ liệt kê để tester test thủ công (D-099).
- **Mapping key có bước duyệt (D-098):**
  1. Dùng key ghi sẵn trong kịch bản; không có thì tìm trong file nghiệm thu, theo Ads name và resource name (D-104).
  2. Vẫn không thấy thì tìm theo tên gần giống, không phân biệt hoa thường.
  3. Đưa bảng mapping cho tester duyệt trước khi kiểm tiếp.
  4. Key không tìm thấy hoặc không có trên console được ghi chú ngay trong bảng.
- **Cách đọc (D-093):**
  - Tool gọi `firebase remoteconfig:get` của `firebase-tools` với tham số cố định.
  - Tester đăng nhập bằng `firebase login` trong terminal. Token do `firebase-tools` giữ, tool không động vào token.
  - Tuyệt đối không có lệnh ghi.
- **Nền tảng (D-094):** dev trên macOS, người dùng chính trên Windows, nên phải chạy được trên cả hai.
- **Project id (D-100):** tester nhập project id mỗi lần, không lưu bảng ánh xạ.
- **Mặc định phải hỏi đủ project id và versionName (D-103).** Chỉ khi tester yêu cầu khác thì mới chạy không có console (trạng thái key lấy từ log, report ghi rõ).

## Kết quả đọc thử template thật (bước 1, 2026-11-08)

Project `aap884-drama-short`, tài khoản ở D-092, `firebase-tools` 15.35.0, chạy trên macOS. Template chỉ lưu tạm ở scratchpad, không commit.

- **Đọc được bằng tài khoản người dùng.** Không cần service account hay OAuth client riêng.
- **Dùng `remoteconfig:get --project <id> --json`, đọc stdout**, không cần file tạm.
  - JSON trả về có `result.conditions`, `result.parameters`, `result.parameterGroups` và `result.version` (`versionNumber`, `updateTime` theo UTC, `updateOrigin`, `updateType`).
  - `result.version` có thông tin người cập nhật; tool phải bỏ trường này.
  - Lệnh `-o <file>` không ghi `version`.
  - Cảnh báo `npm warn` đi ra stderr nên không lẫn vào JSON.
- **Thời gian:** khoảng 3,4 giây mỗi lần gọi qua `npx` khi gói đã có trong cache.
- **Lỗi:** project không tồn tại trả `{"status":"error","error":"Failed to get Firebase Remote Config template for project …"}` với mã thoát 0. Lỗi không phân biệt sai project hay thiếu quyền, nên thông báo phải gộp hai khả năng.
- **Cấu trúc:**
  - 86 key: 24 key ngoài nhóm, 62 key trong 10 nhóm. Tên nhóm theo màn hình: Splash, LFO, LFO1, LFO2, OB, OB1, NFS1, NFS2, Survey, "Giải pháp".
  - Mọi key đều có `valueType`: BOOLEAN 52, NUMBER 18, STRING 14, JSON 2. D-099 xác định theo `valueType`, không đoán từ giá trị.
  - Không thấy `useInAppDefault`.
  - Console không chứa ad ID (không có `ca-app-pub`), nên ID vẫn lấy từ kịch bản và log.
- **Condition:**
  - Có 2 condition: `tester1.0.0` (`app.version.==(['1.0.0'])`) và `auto_test` (version `1.0.0` và quốc gia VN, không key nào dùng).
  - **Tên thật là `tester1.0.0`, không phải `Tester_1.0.0`** (xem [Q-075](open-questions.md)).
  - Chỉ 12 key có giá trị riêng cho `tester1.0.0`; phần lớn key chỉ có default, nên ghi chú của D-096 sẽ xuất hiện ở đa số key.
- **Cách đặt tên key:**
  - Key HF có hai kiểu: `fo_hf_<tên>` (`fo_hf_banner_splash`) hoặc `<tên>_2ID` (`fo_native_survey_2ID`, `resume_2ID`).
  - Key ad in-app không có tiền tố `fo_` (`native_medium`, `banner_all`, `reward_coin`, `reward_unlock_episode`).
  - Có tên lệch so với nhóm: nhóm NFS1 chứa `fo_hf_native_full_scr2`, nhóm NFS2 chứa `fo_hf_native_full_scr1`. Đây là lý do bảng mapping phải được tester duyệt.
- **Chưa kiểm:** gọi `firebase` trên Windows.

## Luồng làm việc của tester

1. **Cài và đăng nhập một lần** trong terminal: `npm install -g firebase-tools` rồi `firebase login` (D-105).
2. **Lập bảng mapping:** agent gọi `map_remote_keys` (file kịch bản, sheet, file nghiệm thu, `firebase_project_id`, `version`). Kết quả là bảng mapping và file `key-map-*.md`. Agent hiện bảng, tester sửa bằng lời, agent truyền phần sửa qua `key_overrides` và gọi lại (D-105).
3. **Sau khi tester duyệt:** agent gọi `verify_ads` với cùng project id, version và `key_overrides`. Trạng thái bật/tắt lấy từ console, log dùng cho load, show, thứ tự.

## Rủi ro đã biết

- Token của `firebase-tools` có quyền ghi Remote Config, và tài khoản là Editor. Việc chỉ đọc do code bảo đảm, bằng danh sách lệnh cố định và test (D-093).
- `firebase-tools` lưu refresh token dạng chữ thường trong thư mục cấu hình của user. Đây là ngoại lệ đã chấp nhận ở D-093.
- Tên gần giống có thể sai, nên tester phải duyệt bảng mapping trước khi kiểm.
- Template lúc gọi tool có thể khác lúc test (Q-063). Report ghi version và thời điểm cập nhật template (UTC); log ghi giờ máy, nên tool chưa tự so hai mốc này.
